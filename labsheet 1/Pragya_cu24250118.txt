TASK 4: PERFORMANCE RISKS OF DYNAMIC UI FETCHING FROM DATABASE
================================================================================

* Database Connection Bottleneck: Executing DB queries for UI layouts on every
  single click rapidly exhausts the connection pool under concurrent traffic[cite: 1].
* Excessive Latency: Query execution time plus network round-trips adds heavy
  overhead before the client can begin rendering[cite: 1].
* Core Web Vitals & SEO Degradation: Prevents static optimization (SSG/CDN),
  causing severely poor Time to First Byte (TTFB) and First Contentful Paint (FCP)[cite: 1].

TASK 6: DECOUPLING FRONT-END PRESENTATION FROM BACK-END LOGIC
================================================================================

Decoupling front-end presentation from back-end logic enforces a clean separation
of concerns[cite: 1]. When the user interface communicates with backend services purely
through versioned API endpoints, teams can refactor UI frameworks, update design
systems, or optimize backend algorithms independently[cite: 1].

This decoupled architecture prevents cascading failures across tiers, enables
independent horizontal scaling of components, and allows a single unified API to
serve multiple client platforms simultaneously (e.g., Web, iOS, Android)[cite: 1].
